# 恢复与批次

恢复前读取 `README.md`、`docs/PROGRESS.md`、本机 `private/progress.json` 和 `private/reviews/`。运行 `python3 scripts/pipeline.py check-sources`，确认 370 份 TXT 与 VTT 未改变，再运行 `status`。如果本机配置缺失，用原盘点清单和源目录重新 `ingest`；原有状态会保留。

首批 3 篇用于建立真实产量和审稿方式；当前完成数见进度快照与机器清单。每批建议 2–3 篇；写作与核对按篇保存，不将整批同时标完成。准备输入并不占用“已写完”状态。中断时从具体未完成的源时间段和正文末段继续，先检查重叠与遗漏。

分块文件只把全部字幕 cue 连续分配，并不提供可信的自动主题分章。可以据其定位源时间，但不能把分块数或覆盖表中填入的布尔值当作语义完整性的证明。

本机 `private/batches/005-plan.json` 是建议下一批：ADHD 与专注、习惯形成、工作记忆。仅准备了输入，状态仍是 pending；恢复时先查看最新 progress，避免重复派稿。正式选题前查看目录，避免将 Essentials 与长版同时生产或以索引日期冒充原版日期。Guest Series 的篇幅可能显著更长，应单独估量。

代码 Git 历史不含私有正文。备份私有目录需要用户已有的本地/私密存储路径；不可为备份擅自把全文推到代码仓库、Library 或新共享服务。当前会话结束后没有自动后台生产；下一次任务须按此清单恢复。
